Kernels

Part 10 of Block Diffusion Rooflines (Previous: 9 · The measurement stack | Next: 11 · Conclusion)

With the engine fixed, two components of TD's step remain far below their rooflines: the routed experts, and global attention at head dimension 512. This chapter explains why each loses time, rewrites both, and measures what the rewrites change in efficiency, throughput and quality. It defines every hardware term it uses.

Terms

The H200 is a Hopper GPU. The terms below are used throughout this chapter.

  • SM (streaming multiprocessor): one of the 132 independent processors of the chip, each with its own tensor cores (the matrix-multiply units), registers and shared memory.
  • CTA (thread block): a group of threads that runs on one SM and shares its shared memory; a kernel launch is a grid of CTAs. A cluster is a group of CTAs, here two, that run at the same time on different SMs and can read and write each other's shared memory.
  • Registers and shared memory: 256 KB of registers and about 227 KB of shared memory per SM. Matrix-multiply accumulators live in registers; operand tiles are staged in shared memory before the tensor cores read them.
  • Tile and pipeline stage: a CTA computes one block of the output, its tile, and streams the operands it needs through shared memory in chunks. With two or more stages (buffers), the next chunk loads while the tensor cores work on the current one; with one, loading and computing alternate.
  • TMA: a copy engine on each SM that moves a whole rectangular tile from memory to shared memory with one instruction.
  • FP8 scaling: an FP8 number has a narrow range, so a block of values shares a scale \(s\), and \(x\) is stored as \(\mathrm{round}(x/s)\). The scale can be per tensor or per row ("per token").

The experts

An MoE layer of DiffusionGemma has hidden size \(d = 2816\), \(E = 128\) experts of width \(f_E = 704\), and \(k = 8\) experts per token. For a token \(x_t\) routed to expert \(e\) with weight \(p_{t,e}\),

\[ h_{t,e} = \mathrm{gelu}\bigl(x_t W_{g,e}^{\top}\bigr) \odot \bigl(x_t W_{u,e}^{\top}\bigr), \qquad y_t = \sum_{e} p_{t,e}\, h_{t,e} W_{d,e}^{\top}: \]

a first GEMM with the gate and up matrices \(W_g, W_u\) and a second with the down matrix \(W_d\). For \(N\) tokens touching \(U\) experts, with \(\bar m = Nk/U\) rows per touched expert on average, the layer does \(F = 6Nk\,d f_E\) FLOPs and reads \(Q = 3U d f_E\) bytes of FP8 weights, so its intensity is \(F/Q = 2\bar m\). The empirical ridge point is 340 FLOP/byte, so the layer is compute-bound above about 170 rows per expert, which TD reaches from batch 8 on, and at batch 4 at long context.

vLLM's two expert GEMMs are not slow: profiled at batch 32, they take the same time as the replacement's. The time is lost between them, in passes that write intermediate tensors to memory and read them back.

The new expert path removes three passes over memory; its two GEMMs are as fast as vLLM's.

One MoE layer at TD batch 32 (\(Nk = 65{,}536\) rows, each a (token, expert) pair). Each box is one kernel, in order; the orange number is what it writes to memory, read back by the next kernel.

The replacement, moe_ws, makes four changes.

  • Weights rewritten once. The gate and up matrices are padded with zero rows from 704 to 768 and interleaved in blocks of 128, and \(W_d\) is padded to 768 columns. The padding is exact: a padded column has gate and up equal to 0, so \(h = \mathrm{gelu}(0)\cdot 0 = 0\), which meets a zero column of \(W_d\). A tile of the first GEMM then holds 128 gate columns next to their 128 up columns, so the activation can be applied in registers.
  • First GEMM with the activation. Each CTA takes 128 rows of one expert, gathers the corresponding rows of \(x\) directly and quantises them to FP8 per token inside the kernel.
  • One pass to quantise \(h\). The FP8 scale of a row of \(h\) needs its maximum over all 768 columns, which no single tile sees, so a light kernel converts \(h\) to FP8 with one scale per row.
  • Second GEMM with the reduction. The epilogue multiplies each row by its routing weight and adds it into the token's output with atomic additions. A token's 8 contributions meet in the L2 cache, so the 369 MB of rows per (token, expert) pair at batch 32 never reach memory.

The expert path is 19–28% faster, and the TD step 4–8%. The patch applies to TD only: an AR step sends 1–64 tokens through a layer, and there the patch is 9% slower. GSM8K on 250 problems is 96.8% with and without it.

The best kernel available at the same shape is cuBLAS on one large GEMM with all \(Nk\) rows stacked, which needs no padding per expert. At batch 32 it runs the first GEMM at 0.96 of the FP8 ceiling and the second at 0.72, 0.81 of the empirical roofline together: a perfect grouped kernel would just reach 0.8. Nsight Compute, NVIDIA's kernel profiler, locates the rest of the gap inside the two Triton GEMMs. The first keeps the tensor cores busy 69% of the time, because with one CTA per SM nothing loads the next tile while a tile finishes. The second is bound by latency at 41%, with two CTAs per SM. What would close it is what cuBLAS has and Triton does not expose on Hopper: separate producer and consumer warps, TMA loads shared across a two-CTA cluster, and an epilogue that overlaps the next tile.

Global attention at head dimension 512

Five of the 30 layers attend globally, with 16 query heads, 2 key/value heads and head dimension \(d = 512\). In a denoising pass the \(L_q = 256\) canvas queries of a sequence attend to its \(L_k = C + 256\) keys, so

\[ F = 4\,L_q L_k\, d\, H_q, \qquad Q \approx 4\,L_k\, d\, H_{kv}, \qquad \frac{F}{Q} = \frac{L_q H_q}{H_{kv}} = 2048 \ \text{FLOP/byte}, \]

14 times the ridge point of the attention ceiling, \(\hat\pi_{\mathrm{attn}}/\hat\beta \approx 148\): the kernel should run at the attention ceiling. FlashAttention 4 runs at 296–357 TFLOP/s here, against 700–729 at head dimension 256 on the same rows. The head dimension is the cause. A CTA keeps its output rows in registers in FP32, \(4md\) bytes for \(m\) rows: 128 KB at \(m = 64\), half of the register file. In shared memory the query tile and one stage of keys and values take

\[ \underbrace{64 \cdot 512 \cdot 2}_{Q} + \underbrace{64 \cdot 512 \cdot 2}_{K} + \underbrace{64 \cdot 512 \cdot 2}_{V} + \underbrace{64 \cdot 64 \cdot 2}_{P} \ \text{bytes} = 200\ \text{KB}, \]

so a second stage does not fit in 227 KB, loading cannot overlap compute, and Nsight Compute finds the tensor cores busy 36% of the time.

The pair kernel, attn512, splits the head dimension across the two CTAs of a cluster. With \(Q = [Q_0\ Q_1]\), \(K = [K_0\ K_1]\), \(V = [V_0\ V_1]\) split at column 256,

\[ S = QK^{\top} = Q_0K_0^{\top} + Q_1K_1^{\top}, \qquad O_r = \mathrm{softmax}(S)\,V_r \quad (r = 0, 1). \]
Figure 18

Each thread block of the pair holds half of the head dimension; the only traffic between the two SMs is the partial score tile.

Both blocks process the same 128 query rows. The orange arrows are the exchange: each block writes its \(m \times n\) partial scores into the partner's shared memory and waits for the partner's before the softmax.

Figure 19

Splitting the head dimension makes room for a second pipeline stage.

Shared memory per thread block, in KB, against the 227 KB of one SM. FA4 at head dimension 512 holds full-width tiles and fits one stage; a block of the pair holds half-width tiles and fits two stages of 64 keys plus two exchange buffers. With 80-token KV pages the fastest configuration uses the room differently, for one stage of 80-key tiles loaded by TMA (Table 18).

Each CTA thus solves a head-dimension-256 problem, small enough for two stages or for larger tiles of keys, at the price of one exchange per tile of keys: it sends its partial scores into the partner's shared memory and waits for the partner's. Per tile a CTA does \(4mn\,(d/2)\) FLOPs and sends \(mn\) FP16 scores, 512 FLOPs per byte crossing between the SMs. Without the exchange (a diagnostic with wrong results) the pair would run at 711–723 TFLOP/s; with it, each tile waits about 0.5 µs for synchronisation and 0.67 µs for the transfer, against 1.5 µs of tensor work. The fastest of the fifteen exchange variants tried uses 16-byte asynchronous stores into two alternating buffers.

The KV cache is stored in pages of a fixed number of tokens. When a page equals the kernel's tile of keys, keys and values load by TMA, so TD uses pages of 80 tokens with the pair kernel, whose fastest configuration has one stage of 80-key tiles. Global attention then runs 1.36–1.37 times faster than FlashAttention 4 at its best page size. Timed alone on the engine's layout, the pair kernel reaches 0.71–0.74 of the attention ceiling (0.73 at the shapes of the grid), so the engine loses little beyond the kernel itself. At batch 1, where a pass holds fewer than 512 queries, the pair kernel is slower than FlashAttention 4, which keeps those calls.
